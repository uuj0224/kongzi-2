# 孔子问答系统两期建设方案

## 目标与约束

个人开发，Python 为主，独立网页，建议总周期四周。用户已决定使用 DeepSeek，费用不设预算上限。第一期交付完整软件，第二期深化检索与回答质量。本轮仅实现第一期。

项目围绕《论语》及孔子相关史传和儒家经典，回答展示可追溯出处，并区分孔子语录、史传记述与现代延伸。

## 技术选型

Vue 3 + TypeScript + Vite + Element Plus；FastAPI + Pydantic；SQLite 保存会话；本地 BGE-small-zh-v1.5 与 NumPy 精确余弦检索；DeepSeek 官方 API 生成回答。模型名称可配置，基线实验固定版本。单机规模不引入 Redis、微服务或独立向量数据库。

我的取舍：先保证问答证据链和可运行性，把第二期投入检索算法和实验；不增加数字人、语音和模型训练。

## 一期交付

建议第 1–10 天：资料整理、原文浏览、基础向量问答、引用定位、会话记录、错误处理、80 条项目整理释义、启动与演示文档。

资料从 GitHub 固定版本导入，包含《论语》二十篇、《史记》孔子世家和仲尼弟子列传、《礼记》五篇。《孔子家语》候选底本含正文注释混排，暂缓入库。详见来源文档。

接口：POST /api/chat；GET /api/health、/api/catalog、/api/passages、/api/passages/{id}、/api/conversations、/api/conversations/{id}。问答返回答案、引用、候选、状态、耗时、模型与 token 用量。

流程：问题规范化 → 本地向量检索前5条 → 带证据生成 → 引用ID校验 → 展示并保存。引用无效时隐藏生成答案，保留候选原文供查阅。

验收：完整页面可运行，全文可浏览，引用可定位，会话可恢复，输入和模型服务异常有明确反馈。测试不依赖付费接口；真实模型验收需配置新密钥。整理释义尚需教师复核，不宣称已完成人工专家审校。

## 二期深化（未实现）

建议第 11–24 天：jieba + BM25 与向量双路召回，RRF 融合，BGE-reranker-base 重排序；开发集校准证据不足阈值；增加实验结果展示。两路各取20，RRF常数60，融合最多30，重排取5，参数仅在开发集调整。

120题人工检查问题集：古文查询、现代释义、思想情境、不可回答各30。分层划分40题开发集与80题冻结测试集，近似改写放同一集合。

比较A仅向量、B混合检索、C混合+重排、D增加证据不足判断。固定知识库、模型及生成参数，分别报告Recall@5、MRR@5、人工正确性与证据支持评分、拒答和误拒答率、耗时与token。

交付四种策略、评测脚本、冻结数据、逐题输出、图表和10个案例。不保证指标一定提高；无提升也保留结果并解释。第25–28天用于修复、文档和答辩。

## 验证与边界

检查导入完整性、稳定ID、检索排序、过期索引、非法引用、会话持久化、超时限流和输入约束。单机单用户，每次独立检索，无登录和公网部署。模型密钥仅由环境变量读取，不进入文档或仓库。

我的判断：一期做到“有完整问答证据链”，二期做到“能用实验解释改进的作用与代价”，更适合在有限周期内体现技术深度。

## 界面交付范围

仅支持桌面浏览器 Web 端，建议窗口宽度至少 1100px；不提供手机布局、App、小程序或桌面安装客户端。
